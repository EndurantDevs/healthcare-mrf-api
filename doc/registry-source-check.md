# Registry source checks

`registry-source-check` checks candidate source bytes without admitting datasets, publishing generations, changing accepted editions, or merging network/company identities. The registered single-job adapter uses queue `arq:RegistrySourceCheck`, worker class `process.RegistrySourceCheck`, and target `process.registry_source_check.control_start`. It uses the existing control lifecycle, cancellation flag and terminal metrics. The dedicated worker accepts one job at a time, one attempt and a finite job deadline.

Control requests contain exactly four required logical fields: `source_system`, `source_id`, `edition_policy` and `reporting_year`. The year may be null for the latest CMS edition policy. Supported source pairs are CMS `commercial-mlr`, CMS `plan-finder`, and NAIC `company-listings`; policies are `latest-verified` and `fixed-year`. A fixed year requires an integer year. URLs, cache paths, roles, DSNs, SQL, environment overrides, parser overrides and test transports are not control parameters.

The trusted operator environment variable `HLTHPRT_REGISTRY_SOURCE_CHECK` contains a closed JSON document with `cache_dir` and `scopes`. The cache directory must be an absolute directory without symbolic links, owned by the effective process user with no group or other access. New cache directories use mode 0700; existing directories are rejected rather than having their permissions changed. `scopes` is a nonempty array of at most 100 exact four-field logical scopes. The selected control scope must be in this allowlist. Optional `max_cache_bytes` defaults to 2 GiB and accepts 32 MiB through 8 GiB; `max_cache_files` defaults to 256 and accepts 32 through 4096. A cache-wide nonblocking native file lock protects the census, reservation, downloads, preparation and checkpoint. Capacity or local free-space shortfalls refuse before network access. Existing candidate files are never evicted automatically.

CMS checks use the existing official bounded catalog discovery, explicit edition selection, guarded download and ZIP/input preparation. Plan Finder accepts only the inspected HIOS workbook layout; RBIS is not parsed. MLR retains the selected header input and lookup fingerprint. An HTTP validator or catalog link never proves artifact acceptance, reporting dates or source coverage.

NAIC requires a separately configured `naic` object with exactly `edition_id`, `source_url`, `artifact_sha256` and `layout_sha256`. The URL and archive digest are trusted operator pins and still pass the existing download URL and byte guards. `layout_sha256` maps exactly `HLTH.csv`, `GPAL.csv` and `GPNM.csv` to verified layout-PDF digests. Preparation binds all three listing members and their PDFs from the same pinned archive. Only fixed reporting year 2026 is supported. Missing pins, other years, latest-NAIC requests and unknown layouts return `review_required`. This job does not discover a current/latest NAIC edition or publish a NAIC dataset.

The existing refresh-intent rules select Monday 03:00 UTC weekly windows for Plan Finder and first-of-month 03:00 UTC windows for MLR and NAIC. Each successful preparation retains one atomic per-scope checkpoint with the exact scope, compiled parser/operator profile, checked clock, window key and raw receipts. `already_checked` requires the same profile/window and revalidation of retained raw bytes, catalog selection and prepared input; file modification time is not a freshness proof. A changed parser or operator pin requires a new check.

Results contain `prepared`, `already_checked`, `unavailable`, `review_required`, `busy` or `not_due`, the logical scope/window, and candidate metadata when verified. Candidate metadata contains source/edition/year/parser, raw and prepared fingerprints, byte counts and applicable member/layout/lookup evidence. Publication time stays unknown unless explicit verified provenance supplies it. Paths, source URLs and source records are excluded. Network/catalog unavailability is a successful bounded check and does not overwrite the prior valid candidate. A prepared candidate still requires separate review and native admission; it grants no serving authority.

The CLI checks configured scopes sequentially. Control dispatch checks one selected scope. Cancellation drains preparation before releasing the cache lock and preserves the prior checkpoint. Scheduler registration and policy ownership remain with the control service; this module creates no scheduler service, database, table or publication authority.
